Audit Form

A PHP and MySQL workflow for recording application audits and making security findings easier to find during review.

  • PHP
  • MySQL
  • JavaScript
  • HTML/CSS

Project overview

I developed an audit-recording workflow for the internal Texas A&M University–San Antonio Web Development Portal. An audit stores the application name, last audit date, audit author, and notes in MySQL. The first version focused on entering and retrieving records. Later iterations made a growing set of audits easier to review.

I worked on the submission handler, the audit list, an accordion view, a toggle between the two views, and the way audits with security findings appear in the results.

How the audit workflow works

Safeguards for recording and reviewing audits

  • Invalid submissions

    The handler checks required fields, dates, field lengths, and the CSRF token before inserting the record. The page can report validation and database errors.

  • False alarms in audit notes

    A phrase match for “security vulnerability” could flag notes that report zero findings. The later query checks for a positive finding before prioritizing a record.

  • Markup in stored text

    The interface escapes application names, authors, and notes when displaying them. Local tests confirmed that markup-like input appeared as plain text.

What the tests showed

I tested the views using 15 audit records, checking the initially collapsed accordion, five-record pagination, list metadata, view switching, the details modal, and the priority order for findings. The local MariaDB query and automated browser checks passed, including the pagination and escaping checks.

I confirmed the earlier list and accordion toggle in the development workflow. The later version with priority ordering and severity indicators passed local preview checks. Integration of that later version with the live portal remained unverified in the development notes.
