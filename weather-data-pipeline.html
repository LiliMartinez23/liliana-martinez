Weather data pipeline

A staged CSV import for 11 weather stations, with checks for missing, duplicate, and malformed readings.

  • MySQL
  • SQL
  • Bash
  • WSL
  • cron

Project overview

I built this project to keep the latest weather readings from 11 stations in one place. When the program finds a new file, it checks for repeated stations and loads the readings into a separate table before updating the main one. I wanted to see which problems the program would flag and whether the last good set of readings would stay available when a file had an issue.

How the pipeline works

Three intentional failure tests

These deliberate tests check what appears in the load log and which readings reach the final table.

  1. Omit a station row

    Remove one row for a station that was present in the last good load.

    Expected resultThe load log identifies the missing station by comparing the new batch with the previous readings.

  2. Duplicate a station row

    Add a second copy of a row with the same station ID.

    Expected resultBash flags the repeated station ID in the load log and stops before any rows are imported.

  3. Put text in a numeric field

    Replace a temperature with X.

    Expected resultThe load log shows a warning. MySQL can turn the invalid temperature into zero and finish the import, so this test also checks the final readings. MySQL reference

What the results show

The duplicate check flagged a repeated station in an archived CSV. A manual recovery with a clean file confirmed that staging and the final table held the same 11 readings.

The missing-station and invalid-temperature examples show expected behavior.
